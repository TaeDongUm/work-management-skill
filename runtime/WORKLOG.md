## 중요한 작업·방향 변경

비밀키·토큰·불필요한 개인정보를 기록하지 않는다.

## 오류·수정
| E ID | 재현 조건·실제 증상 | 가설·확인된 원인 구분 | 수정 범위·파일 | 재검증 V ID·결과 | 남은 위험 |
|---|---|---|---|---|---|

에러가 사라졌다는 사실과 원인을 확인했다는 사실을 구분한다.
문서만으로 해결 표시하지 않고 실행 근거를 연결한다.

## 이해 확인 참조
실제 사용자 설명·교정은 UNDERSTANDING.md의 U ID 한 곳에서 관리한다.
작업표에는 관련 U ID와 다음 행동만 연결하고 같은 설명을 복사하지 않는다.

## AI 위임·선택 기록

## 보완 작업 상세 — 기존 작업표의 T ID 참조
| T ID | 평가 항목·R ID | 완료 기준 | 검증 V ID 또는 이해 U ID | 예상 소요(추정) | P0/P1/P2·근거 |
|---|---|---|---|---|---|

작업 상태·다음 행동은 위 작업 체크리스트 한 곳에서 관리한다. 같은 결함은 여러 평가 항목에 걸쳐도 하나의 작업으로 묶는다.
P0 필수·정확성·안전·제출 차단 / P1 중요한 검증·예외·이해 공백 / P2 낮은 영향 개선.
모든 부족을 즉시 구현하지 않는다. 상위 최대 3개부터 수행하고 관련 항목만 재점검한다.
