## 작업 체크리스트
| T ID | 작업 | R ID | 우선순위 | 상태 | 관련 V ID | 다음 행동 |
|---|---|---|---|---|---|---|

상태: 대기 / 진행 중 / 구현됨 / 검증됨 / 차단 / 보류.
구현됨은 완료를 뜻하지 않는다. 요구가 바뀌면 작업과 검증의 연결도 갱신한다.

## 중요한 작업·방향 변경
| 기록 ID | 수행·발견한 내용 | 변경 파일·D ID | 결정 이유 | 결과·V ID | 다음 행동 |
|---|---|---|---|---|---|

모든 명령을 복제하지 않는다. 우선순위 변경·기능 완료·중요한 발견 중심으로 기록한다.
비밀키·토큰·불필요한 개인정보를 기록하지 않는다.

## 오류·수정
| E ID | 재현 조건·실제 증상 | 가설·확인된 원인 구분 | 수정 범위·파일 | 재검증 V ID·결과 | 남은 위험 |
|---|---|---|---|---|---|

에러가 사라졌다는 사실과 원인을 확인했다는 사실을 구분한다.
문서만으로 해결 표시하지 않고 실행 근거를 연결한다.

## 이해 확인
| U ID | 질문 | 확인한 코드·설계 | 실행 근거 V ID | 사용자 자신의 설명 | 남은 의문 |
|---|---|---|---|---|---|

사용자의 설명은 실제로 제공받은 경우에만 기록한다. AI가 쓴 설명은 'AI 설명, 사용자 확인 전'이라고 구분한다.
핵심 데이터 흐름·규칙·구조 선택·실패 조건에 집중한다. 모든 문법 질문을 기록하지 않는다.

## 작업 종료 때 갱신
현재 상태와 체크리스트를 갱신하고, 새 오류·중요 결정만 추가한다.
REQUIREMENTS·DESIGN·VERIFICATION 내용을 중복 복사하지 말고 ID를 참조한다.

| 평가 항목 ID | 판정 | 실제 근거·파일·V/U ID | 부족한 점·영향 | 연결 T ID 또는 보류 이유 |
|---|---|---|---|---|

판정: 충족 / 부분 충족 / 미충족 / 미확인 / 해당 없음.
AI가 쓴 설명을 사용자 이해의 근거로 삼지 않는다. 확인하지 않은 항목은 미확인으로 남긴다.

## 보완 작업 상세 — 기존 작업표의 T ID 참조
| T ID | 평가 항목·R ID | 완료 기준 | 검증 V ID 또는 이해 U ID | 예상 소요(추정) | P0/P1/P2·근거 |
|---|---|---|---|---|---|

작업 상태·다음 행동은 위 작업 체크리스트 한 곳에서 관리한다. 같은 결함은 여러 평가 항목에 걸쳐도 하나의 작업으로 묶는다.
P0 필수·정확성·안전·제출 차단 / P1 중요한 검증·예외·이해 공백 / P2 낮은 영향 개선.
모든 부족을 즉시 구현하지 않는다. 상위 최대 3개부터 수행하고 관련 항목만 재점검한다.
