# 데이터 지도
상태: 과제 시작 전. 전체 행을 외우는 대신 한 행의 의미·연결·단위·결정에 필요한 값을 이해한다.
원본은 보존한다. 데이터가 없다는 사실과 값이 소실됐다는 원인 추정을 구분한다.

## 파일별 개요
| 자료 ID | 실제 경로·버전 | 한 행의 의미 | 전체 건수·확인 방법 | 핵심 키·연결 대상 | 사용하는 결정·R ID |
|---|---|---|---|---|---|

## 핵심 필드와 문제
전체 필드는 코드로 조사하되 아래에는 의사결정에 중요한 것만 기록한다.
| 필드·자료 ID | 의미·단위·시점 | 결측·중복·범위 이상 건수 | 전체 검사/표본 검사·명령 | 처리안·영향 | 관련 R/D/V ID |
|---|---|---|---|---|---|

## 없는 정보 구분
| 필요한 정보 | 유형 | 확인한 근거 | 무엇을 결정할 수 없는가 | 대응·가정·질문 ID |
|---|---|---|---|---|
유형: 일부 행의 결측 / 필드·자료 자체 없음 / 의미·단위 불명 / 업무 정책 미확정 / 원자료 간 충돌.
버스 대수 상한은 정책일 수 있고, 좌표 누락은 데이터 결측이다. 군집화 방법은 보통 설계 선택이다. 모두를 결측값으로 묶지 않는다.
추정·대체값은 원본과 구분하고 근거·결과 영향을 기록한다. 누락을 임의로 0으로 채우거나 행을 삭제하지 않는다.

## 대표 한 건 추적
- 원본 행·키(필요 이상의 개인정보 제외):
- 연결되는 다른 자료와 조인 키:
- 입력 → 변환 → 결정에 쓰이는 값 → 출력:
- 누락/중복 키로 결합할 때 건수가 달라지는지:
- 내가 설명했는지: UNDERSTANDING의 U ID 참조.

## 범위와 갱신
첫 조사와 데이터/처리 규칙 변경 시 갱신한다. 전체 검사하지 않았다면 전체 데이터에 이상이 없다고 주장하지 않는다.
현재 유효한 핵심 수치만 유지하고 주요 변경은 WORKLOG에서 연결한다.
