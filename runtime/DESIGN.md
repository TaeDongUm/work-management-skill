- 기존 기술·구조:

## 중요한 설계 결정
| D ID | 결정 | 근거 R ID·제약 | 대안 | 선택 이유·대가 | 관련 파일 |
|---|---|---|---|---|---|

단순한 문법 선택까지 기록하지 않는다. 결과의 신뢰성·유지·사용성에 영향을 주는 결정을 기록한다.
UI 결정은 중요한 것 최대 5개부터 시작한다. 선택이 부적합해지는 조건은 아래 한계 표에, 확인할 방법은 VERIFICATION의 V ID로 연결한다. 기대 효과와 실제 측정 결과를 구분한다.
프런트엔드에서 숨기는 것과 서버 접근 통제를 구분한다.
가짜 응답·모의 데이터·실제 연결을 명확히 표시한다.

- 입력·단위·자료 ID:
- 결정 변수(우리가 정할 값):

- 유효성·최적성 보장 범위 / 실행 비용·제한:

- 조건을 만족할 수 없을 때 처리:

## 기술 선택
| 기술·버전 | 담당 역할 | 이 과제에서 선택한 근거 | 대안·선택의 대가 | 변경이 필요한 조건 |

기존 환경·데이터 규모·시간·실행 요구를 근거로 적는다. 일반적인 장점만 나열하지 않는다.
