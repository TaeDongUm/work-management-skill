# 내 이해와 설명 확인
상태: 과제 시작 전. 서술형 답안 원고가 아니라 작업 중 이해를 확인하는 짧은 색인이다.
AI 사용이 허용된 작업·연습 단계에서만 사용한다. 후속 문항 중 열람·AI·복사 가능 여부를 가정하지 않는다.
REQUIREMENTS·DATA_MAP·DESIGN·VERIFICATION·WORKLOG를 재복사하지 않는다. 핵심 요약과 근거 ID만 연결한다.

## 과제 설명 — 처음 조사한 뒤 내 말로
- 누가 어떤 문제를 겪는가:
- 어떤 입력으로 무엇을 결정해 어떤 결과물을 내야 하는가:
- 반드시 지킬 조건 / 개선할 목표 / 하지 않을 것:
- 지금 결과를 가장 크게 바꿀 미확정 조건:
- 한 건의 입력이 완료되는 예:

## 실제로 설명해 본 기록
| U ID | 시점·질문 | 근거 문서 ID·실제 파일/함수·V ID | 사용자 실제 설명 | 교정할 점 | 상태·다음 확인 |
|---|---|---|---|---|---|
상태: 아직 설명 안 함 / 부분 이해 / 해당 질문 설명 확인 / 변경 후 재확인.
AI 설명은 별도로 'AI 설명, 사용자 확인 전'이라 표시한다. 사용자의 답변·승인·실행을 대신 작성하지 않는다.

## 우선 확인할 여섯 질문
1. 과제와 데이터: 무엇을 결정하며 어떤 정보가 없고 그 영향은 무엇인가?
2. 선택: 왜 이 스택·계산 방식을 택했고, 대안과 포기한 것은 무엇인가?
3. 구조: 대표 입력이 실제 어느 파일·함수를 거쳐 계산·저장·표시되는가?
4. 변화: 핵심 값 하나를 바꾸면 어떤 결과를 예상하며 실제로 확인했는가?
5. 오류: 어떤 증상에 AI가 무엇을 제안했고 무엇을 선택·재검증했는가?
6. 검증: AI가 작성·실행한 것, 내가 직접 확인한 것, 아직 모르는 것은 무엇이며 왜 그런가?

## 사용법
초기 조사 후, 중요한 설계 선택 후, 첫 핵심 흐름과 큰 변경 후에 중요한 질문 하나씩 한다.
처음부터 모든 코드를 암기하지 않는다. 실제 모듈명·역할·입출력·호출 관계를 코드에서 찾아 설명한다.
답변 전에 모범답안을 제시하지 않는다. 막히면 실제 코드/작은 입력/실행 근거로 설명한 뒤 다시 자기 말로 답하게 한다.
이해 확인 대기 때문에 무관한 안전한 작업까지 멈추지 않는다. 사용자가 건너뛰면 미확인으로 남긴다.
제출 전에는 미확인 중 영향이 큰 2~3개를 우선한다. 문서만 읽고 이해 완료로 표시하지 않는다.
