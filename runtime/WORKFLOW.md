# 과제 수행 지침
제공 README·기존 AGENTS.md·최신 시험 규정·제출 양식이 우선이다. 원본은 보존한다.
키트는 일반 Markdown 요청문과 기록 양식이며 공식 채점표나 설치형 Skill이 아니다.

## 기록 위치부터 정하기
SUBMISSION_DOCUMENT_GUIDE.md에 따라 제출 양식과 기록 항목의 대응표를 정한다.
지정 문서가 같은 역할을 하면 그 문서에 직접 기록하고 runtime 복제본은 만들지 않는다.
현재 단계·핵심 작업 상태는 WORKLOG에 둔다. 모든 파일을 매번 읽지 않는다.

## 진행 순서와 이해 확인
1. 과제와 데이터를 함께 조사: ../prompts/discovery/00_UNDERSTAND_TASK_AND_DATA.md.
   REQUIREMENTS에 조건·목표, DATA_MAP에 데이터의 의미·품질·부족을 기록한다.
   사용자가 과제와 대표 데이터 한 건을 자기 말로 설명하도록 질문 하나를 한다.
2. 중요한 질문·재질문·역제안: ../prompts/discovery/01_INTERVIEW.md.
   정책·기술 선택·데이터 결측을 구분한다. 미확정 영향 범위만 분리하고 독립 작업은 진행한다.
3. 핵심 해결 방식 설계: ../prompts/design/01_SOLUTION.md.
   계산 문제·기본안·대안·스택·책임 경계·작은 예제의 기대 결과를 정한다.
   중요한 선택의 이유·대가를 사용자가 설명하도록 한다.
4. 작은 핵심 흐름을 입력 → 처리 → 저장/출력까지 구현한다.
   UI가 있으면 ../prompts/ui/01_PLAN.md, 02_BUILD.md를 해당 단계에만 사용한다.
   실제 모듈명·입출력은 DESIGN에 코드 기준으로 갱신한다.
5. 실제 검증과 설명: ../prompts/review/01_REVIEW_AND_EXPLAIN.md.
   화면은 ../prompts/ui/03_REVIEW.md로 필요한 수동 확인을 안내한다.
   첫 핵심 흐름·중요 변경 후 실제 파일/함수를 따라 설명하게 한다.
6. 첫 흐름 이후 필요할 때 ../prompts/review/02_GAP_REVIEW.md로 최대 3개 보완 작업을 정한다.
7. 최종 코드·문서·검증 근거를 대조하고 실제 지정 방식으로 제출한다.

이해 확인은 마지막에 몰지 않는다. 작은 수정마다 퀴즈를 강제하지도 않는다.
실제 사용자 답변만 UNDERSTANDING에 기록한다. 답변 대기는 무관한 안전한 작업을 막지 않는다.

## 작업 지시
목표 / 관련 요구 / 변경 범위 / 유지할 조건 / 완료 기준·검증 / 막힐 때 판단 기준.
핵심 묶음은 우선 3~4개로 정리하되 모든 필수 요구를 연결한다. 세부 작업을 없애는 뜻이 아니다.
확정된 사실·담당자 합의·개발자 결정·임시 가정을 구분한다.

## 검증과 설명
- 계산이 중요한 과제: 작은 수작업 예제 → 독립 제약 검사 → 기준 방식 비교 → 통합 검증.
- 개선 목표와 필수 제약, 유효한 해와 최적해를 구분한다. 근거 없는 최적성·개선 수치는 쓰지 않는다.
- 입력·계산·DB·HTTP·화면의 책임을 나누되 불필요한 계층은 만들지 않는다.
- 기대값은 원문·원자료·확인된 규칙에서 도출한다. 구현 결과를 정답으로 복사하지 않는다.
- 코드 검사/빌드/테스트/실제 사용 흐름/사용자 이해는 서로 다른 근거다.
- AI 위임·실제 실행 주체·사용자 직접 확인·남은 검증을 VERIFICATION에 구분한다.
- 실패·수정 후 같은 조건과 영향받는 검증을 재실행한다. 이전 실행 이력은 보존한다.
- 모든 예외를 구현하지 않는다. 필수 조건 위반·데이터 손실·핵심 결과 오류부터 확인한다.
- 필수 요구 미구현은 합의된 제외로 숨기지 않는다. 한계에는 조건·영향·대응·다음 확인을 적는다.

## 시간·세션
남은 시간은 실제 알려진 값만 사용한다. 이해·구현·검증을 반복하며 최종 제출 여유를 확보한다.
180분 연습 예시: 원문·데이터·질문 25 / 설계·기본 예제 20 / 핵심 연결 65 / 필수 확장·검증·설명 45 / 최종 확인·제출 25.
고정 시간 규정이 아니며 실제 과제·운영 공지에 맞춘다. 필수 초기 절차도 포함한다.
메인 세션 하나가 기본이다. 별도 검토는 사용자가 선택하고 안정된 파일 상태를 기준으로 읽기 위주로 수행한다.
세션 전환·중단에만 HANDOFF를 쓴다. 재접속 후 살아 있는 작업을 확인하고 중복 실행하지 않는다.

## 안전·최종 확인
시험 자료·산출물·대화·비밀값의 외부 전송, Git Push, 제한 우회는 하지 않는다.
현재 시험에서 금지된 외부 AI·개인 API·Computer Use를 쓰지 않는다. 화면 확인은 허용된 내부 브라우저에서 수동으로 한다.
감독·인증·전체 화면 문제는 공식 지원 절차로 처리하고 보호 설정을 우회하지 않는다.
최신 공지가 기존 안내와 다르면 최신 안내를 따른다. 후속 AI 금지 문항에서 이 키트를 쓰지 않는다.
필수 파일·실행법·저장/재조회·최종 검증·알려진 한계를 확인한다. 플랫폼 확인 전 제출 완료라 하지 않는다.
