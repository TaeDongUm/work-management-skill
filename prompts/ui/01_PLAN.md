# 화면 설계 프롬프트
사용 시점: 요구사항을 파악한 뒤, UI 구현 전. UI가 필요 없는 과제라면 생략한다.
기준 경로: 키트 루트. 아래 내용을 작업 요청으로 사용한다.

## 요청
과제 README, 기존 지침·코드와 runtime/REQUIREMENTS.md의 관련 항목을 읽고 최소 화면을 설계해줘. 아직 구현하지 마.

1. 사용자, 핵심 업무, 판단에 필요한 정보, 실수 위험을 정리한다.
2. 이미 제공된 내용을 다시 묻지 않는다. 답에 따라 설계·범위가 달라질 중요한 미확인 사항만 담당자 질문 후보로 제시한다. 나머지는 가정으로 표시한다.
3. 핵심 업무를 끝까지 수행하는 최소 화면과 사용자 행동 순서를 제안한다. 요구되지 않은 로그인·대시보드·차트·애니메이션을 관성적으로 추가하지 않는다.
4. 정상·처리 중·빈 데이터·입력 오류·처리 실패·확인 필요 상태 중 해당하는 것을 설계한다. 결과 판정과 사람의 검토 완료 상태를 혼동하지 않는다.
5. 기존 기술 스택을 우선한다. UI UX Pro Max 없이 시작하며, 특정 문제가 해결되지 않을 때만 도구 사용의 이점과 비용을 검토한다.
6. 주요 결정은 최대 5개부터 runtime/DESIGN.md에 기록한다. 요구 ID와 출처, 선택 이유, 대안, 단점, 선택이 부적합해지는 조건, 검증 ID를 연결한다.
7. 기대 효과는 가설로 적는다. 측정하지 않은 시간 단축·사용성 개선을 사실로 주장하지 않는다.
8. 검증 계획은 runtime/VERIFICATION.md에 기록한다. 문서에는 같은 사실을 반복하지 말고 ID로 연결한다.

## 출력
- 화면별 사용자 목표·핵심 정보·주요 행동을 담은 짧은 표
- 설계를 바꿀 중요한 질문 또는 명시적 가정
- 선택 이유와 구현할 최소 범위
- 갱신한 문서 위치

## 선택 도구를 사용할 때
공개 도구 허용 범위와 실제 동작을 확인한다. 스킬의 추천보다 과제 요구를 우선한다. 전체 자료를 모두 읽지 말고 관련 검색 결과만 활용한다. 디자인 자료 다운로드와 외부 서비스 호출을 구분한다. 외부 전송·외부 AI·개인 인증·자동 브라우저 조작을 요구하는 단계는 실행하지 않는다. 설치가 막히면 우회하지 말고 Codex 단독 설계로 진행한다.
