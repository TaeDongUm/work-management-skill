# 화면 검증·이해 확인 프롬프트
사용 시점: 핵심 사용자 흐름이 완성됐을 때, 큰 변경 후, 제출 전 필요한 범위.
AI 사용이 허용된 작업·연습 단계에서만 사용한다. AI 사용 금지인 제출 후 서술형 단계에서는 사용하지 않는다.

## 요청
현재 코드, 관련 요구·설계와 검증 기록을 대조해 화면을 검토해줘.

1. 사용자가 핵심 업무를 끝낼 수 있는지, 누락된 정보·행동·실패 상태가 있는지 확인한다.
2. 대표 입력이 처리되고 화면에 나타나는 경로를 실제 파일·함수명으로 추적한다. 화면의 상태와 실제 데이터가 불일치할 가능성을 찾는다.
3. 정상 사례와 영향이 큰 예외 사례를 검증한다. 실제 실행한 명령·입력·결과만 VERIFICATION에 기록한다.
4. 코드 검사·빌드 성공과 실제 화면 사용 확인을 구분한다. 허용된 내부 브라우저에서 사용자가 직접 확인할 짧은 절차와 기대 결과를 제공한다. 자동 브라우저 조작이나 캡처는 요구하지 않는다.
5. 설계 이유가 실제 코드와 일치하는지 확인한다. 미측정 효과, 구현되지 않은 기능, 검증되지 않은 주장을 수정한다.
6. 기능을 막는 문제부터 수정한다. 남은 시간이 부족하면 장식보다 필수 동작·검증·제출을 우선한다.

## 이해 확인
핵심 흐름의 동작·설계 이유·실패 조건 중 하나를 골라 질문 하나만 제시한다. 사용자의 답변 전에는 모범 답안을 공개하지 않는다. 이 대기는 이해 확인 대화에만 적용하며 무관한 안전한 검증 작업까지 막지 않는다.

답변을 받으면 실제 코드와 대조해 맞은 부분과 부족한 부분을 짧게 설명한다. 필요하면 해당 코드와 실행 결과를 확인한 뒤 사용자가 자기 말로 다시 설명하도록 한다.

- 질문 예: 이 버튼을 누르면 어떤 데이터가 어느 함수에서 바뀌는가?
- 질문 예: 왜 이 화면 구성을 선택했고 언제 다른 구성이 더 적합한가?
- 질문 예: 입력에 중복이나 누락이 있으면 어디에서 감지하며 어떻게 표시하는가?

질문 → 코드 확인 → 실행 확인 → 사용자 설명 중 실제 수행한 단계만 WORKLOG의 이해 확인 항목에 기록한다. AI가 만든 설명을 사용자 이해로 기록하지 않는다. 사용자가 생략하면 미확인으로 둔다.

## 최종 출력
충족한 요구 / 발견한 문제 / 실제 검증 결과 / 사용자 확인 대기 / 남은 한계를 짧게 보고한다. 점수나 질문 출제를 보장하지 않는다.

공통 데이터·계산·저장·실패 조건 점검은 ../review/01_REVIEW_AND_EXPLAIN.md를 사용한다. 같은 이해 질문이나 검증을 중복하지 않는다. 평가 관점별 부족을 작업으로 바꾸려면 ../review/02_GAP_REVIEW.md를 사용한다.
