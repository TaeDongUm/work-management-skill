다음 변경 사항을 관련 문서와 작업에 일관되게 반영해줘.

[변경 내용 또는 담당자의 실제 답변]
[변경을 발견한 근거·출처]

1. 변경의 시작점을 판단해줘.
   - 요구사항 추가·변경
   - 기존 요구의 재확인
   - 설계 오류·개선
   - 구현 오류
   - 검증에서 발견한 문제

2. 기존 기록과 실제 코드를 확인하고,
   무엇이 바뀌며 무엇은 유지해야 하는지 정리해줘.
   확인된 사실과 가정을 구분하고,
   중요한 업무 규칙이 불명확하면 담당자에게 확인할 질문을 제시해줘.

3. 영향받는 문서만 아래 기준으로 갱신해줘.
   과제에서 지정한 제출 파일이 있다면 기존 대응표의 파일을 사용해줘.
   - REQUIREMENTS:
     요구·합의·완료 기준이 달라질 때 갱신한다.
     재확인이라면 기존 항목의 출처·확인 상태만 갱신한다.
     설계나 코드만 잘못됐다면 요구를 임의로 바꾸지 않는다.

   - DESIGN:
     영향을 받는 구조·처리 방식·화면을 갱신한다.
     이전 선택, 변경 이유, 새로운 선택, 영향과 한계를 기록한다.

   - WORKLOG:
     구현·수정·검증 작업을 추가하거나 기존 작업과 병합한다.
     우선순위, 완료 기준, 다음 행동을 명시한다.
     아직 실행하지 않은 작업은 완료로 표시하지 않는다.

   - VERIFICATION:
     변경된 요구와 위험에 맞춰 검증 계획을 갱신한다.
     기존 검증 중 재실행이 필요한 항목을 표시한다.
     이전 실행 이력은 보존하고, 새 실행 결과는 실제 실행 후 추가한다.

4. 관련 요구·설계·작업·검증 ID를 연결해줘.
   동일한 변경 설명을 모든 파일에 복제하지 말고,
   변경 흐름의 요약은 WORKLOG 한 곳에 남겨줘.
   현재 유효한 내용은 갱신하고 중요한 변경 이력은 보존해줘.

5. 이미 합의된 범위에서 수행 가능한 수정과 검증은 진행해줘.
   추가 확인이 필요한 부분은 대기 상태로 구분해줘.
   실제 구현·검증 후 작업 상태와 결과를 갱신해줘.

마지막으로 다음만 짧게 보고해줘.

- 변경 시작점과 이유
- 갱신한 파일·연결 ID
- 실제 수정·검증 결과
- 확인 대기·남은 한계·다음 행동

prompts/change/01_PROPAGATE_CHANGE.md를 따라 아래 변경을 처리해줘.

[담당자의 답변 또는 발견한 문제]

근거:
[대화 내용, 관련 파일, 실행 결과 등]
