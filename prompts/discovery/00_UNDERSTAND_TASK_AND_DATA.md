# 과제·데이터를 함께 이해하기
사용 시점: 처음 과제를 받았을 때. 원문 요약만 보고 대규모 구현에 들어가지 않는다.

## 요청
과제 README·제출 지침·제공 데이터·기존 실행 구조를 함께 조사해줘.
원본은 보존하고 실제 제출 파일명·위치를 먼저 확인해줘.

1. 업무 문제, 사용자, 입력, 결정할 것, 출력, 완료 기준을 간단히 설명한다.
2. 필수 제약 / 개선 목표·우선순위 / 금지·제외 / 개발자 선택 / 미확정을 구분하고 원문 위치를 붙인다.
   '제한이 안 적혀 있음'을 '무제한'으로 바꾸지 않는다. 명시적으로 무제한이면 불필요하게 다시 묻지 않는다.
3. 데이터 파일별 한 행의 의미·건수·키·관계·단위·시점·범위를 조사한다.
   결측·중복·잘못된 범위·조인 누락을 가능한 한 스크립트로 확인하고 명령과 검사 범위를 남긴다.
   표본만 읽었다면 전체 확인이라 쓰지 않는다. 전체 행을 대화에 출력하지 않는다.
4. 일부 값 결측, 자료 자체 없음, 정책 미정, 알고리즘 선택을 구분한다.
   무엇을 계산/판정할 수 없는지, 추가 자료가 필요한지, 허용된 근사가 가능한지 설명한다.
5. 대표 입력 한 건을 골라 어떤 자료를 연결해 어떤 출력을 낼지 보여준다.
6. REQUIREMENTS·DATA_MAP에 사실을 기록하고, 핵심 작업을 우선 3~4개로 묶는다.
   묶음 수를 줄이려고 필수 요구를 누락하지 않는다.
7. 나에게 '누구의 어떤 문제를 어떤 데이터로 해결하고 무엇을 지켜야 하는가?'를 물어본다.
   내 답변 전에 모범답안을 주지 않고 원문과 대조해 UNDERSTANDING에 실제 답변만 기록한다.
8. 결과를 바꿀 중요한 질문 최대 3개를 01_INTERVIEW.md 방식으로 준비한다.

## 보고 분량
과제 설명 5줄, 핵심 데이터 표, 결정에 중요한 미확정 최대 3개, 다음 행동.
원문·데이터·담당자 답변 간 충돌은 숨기지 않는다. 새 사실이 나오면 요약도 갱신한다.
