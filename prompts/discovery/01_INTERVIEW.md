# 발굴·합의 프롬프트
과제 시작 시 제공 자료를 먼저 읽고 사용한다. 이미 명확한 과제는 짧게 진행한다.

## 요청
README·자료·기존 코드와 runtime/REQUIREMENTS.md를 확인하고, 실제 업무 문제와 중요한 미확인을 정리해줘.
해결책을 먼저 확정하지 말고 아래 관점 중 필요한 것만 질문 후보로 골라줘.
- 실제 사례: 최근 문제가 생긴 한 건과 처리 순서는?
- 현재 처리법: 지금 어떤 자료·도구·임시 방법으로 해결하는가?
- 병목·영향: 어느 단계에서 시간·오류·비용이 발생하는가? 근거 수치가 있는가?
- 당사자: 누가 사용하고 누가 최종 판단하며 이후 누가 유지하는가?
- 경계: 예외·누락·상충 자료·금지 사항·이번에 하지 않을 일은?
- 데이터 원천: 무엇이 기준 자료이고 버전·시점·우선순위는 무엇인가?

각 질문에 '답에 따라 달라지는 설계·판정·우선순위'를 붙여 중요도가 높은 질문부터 소수씩 제시한다.
이미 자료에 있는 답은 다시 묻지 않는다. 3분 대기나 특정 단어 금지를 기계적으로 적용하지 않는다.
재무·시간·사용자·운영 등 관련 관점만 사용하고 과제와 무관한 분야를 억지로 조사하지 않는다.
담당자 답변을 AI가 대신 지어내지 않는다. 답변 전에는 확인 대기로 둔다.

## 합의
중요한 업무 규칙과 범위를 정리한 후 REQUIREMENTS의 합의 요약을 작성해 담당자에게 확인할 메시지를 제시한다.
확인받은 사실만 합의로 표시한다. 숫자나 현재값이 없으면 미확인으로 두고 관찰 가능한 완료 조건을 제시한다.
명확하고 이견 없는 기존 요구는 그대로 진행한다. 모든 구현 세부사항을 승인 대상으로 만들지 않는다.
